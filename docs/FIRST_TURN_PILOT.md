# 新本家首回合局部自主展开与灰后恢复

本文件记录正式 v6 开发中的局部实验和内部组件；它不是对外 v6 规划能力或完整首回合规则认证。

## 2026-10-18 异常证据基础（实施中）

费用支付后的内部故障试验已保留并独立重放待处理前缀：Scythe素材由2变1，牌库特召尚未完成。成功审计前缀不能消除执行故障，亦不能将待处理提示当作结束阶段或恢复操作窗口。测试backend注入明确标为故障模拟；原生审计固定使用ProcessEngineAdapter，所有成功推荐仍须满足实际终场与完整证据条件。

新增独立 `ResumableSearch`：保存frontier、当前层和游标、待排序下一层、完整路径历史、已见状态、候选顺序、展开计数与覆盖缺口；持久检查点绑定知识、目标、目录、初态和预算。恢复前重建既有符号前缀做完整性校验，这会增加校验CPU工作，但不产生新引擎调用，也不把它宣称为性能改善。旧连续搜索保留作回归对照。

`persist`／`load`同时核对账本收费序列、预算及预留令牌所有权。检查点之后出现新调用或预留变化时，拒绝把旧前沿当作当前状态；未知调用继续收费，需要显式恢复流程。此组件尚未接入完整运行中的提示进度、执行恢复和矩阵编排，不能据此宣称端到端续跑完成。

内部局部报告v2新增 `start_partial_v2`、`execute_partial_v2`、`validate_partial_execution_v2` 和独立重放入口。最后实际结果、最后已审计前缀、未执行选择、执行故障与审计故障分别保存。初始worker调用失败时没有可借用的局面，目标及终场状态保持未知；失败调用仍扣费。局部v1读取、严格校验及历史方案ID继续保留。

初始调用先持久化请求及预算意图；在首次调用之前已经没有预算时，用该时点的账本证明未启动，新增消费为0。没有意图不能取得这种拒绝证明，已有收费调用也不能通过改填0来免单。合法局部v1报告继续读取；过大的计数作为非法合同拒绝，不触发算术溢出。

选择和语义预测使用不可覆盖、内容绑定的检查点；同一提示重试不能替换旧记录。查询审计先保存持久意图，失败报告保留已验证见证数量、实际收费调用、失败阶段及原始worker错误。验证器从账本重新取得结果或错误并重算，不采信报告自填进度。序列化不能复制原生审计资格；修改返回报告也会使其运行时凭据失效。

预算截断即使已观察到Rusty＋Fog，也不能在结束阶段处理完成前推荐成功。当前保守预留可能令72次上限在结束前停止；这不证明原目标不可达，也不能把未消费的预留算作消费。

已实现的v2诊断证明覆盖完整审计的旧局部结果、已记录worker错误、初始见证预留不足及其审计进度。未完成的错误分支、未知调用、缺少持久证据或属性无法重建时，仍拒绝完整合同验证。原始失败材料继续保留，不通过放宽比较迁就旧开发报告。完整搜索续跑、剩余74项规则、正式v6和48手评估均未完成。

错误返回与规则验真分别处理：故障注入可测试退出／超时／损坏输出的扣费和分类，但不能授予规则资格。失败前缀可用正常部署另行收费重放；这不能消除原失败或把前缀提升为成功线路。实际命令、报告目录和费用以TESTING.md及持久日志为准。

这是内部局部集成入口，不是正式全构筑 v6。冻结原赛事主41／额外15、资产、core、OCG/MR5、seed1和Rusty＋盖放Fog目标均未改变。

起手为 Decayed Cloak、Tsuchinoko、Soleret、Torn Scales、Doll Hammer。搜索先冻结最多8个自主方案，再选择首个以Scythe为首敏感效果的候选。该选择属于定向集成实验，不是无干扰最高排名推荐。人工对照配方仅在独立测试中使用，搜索实现不读取配方。

本机两次三组实验均通过：

| 组别 | 实际结果 | 调用（含查询见证及首次独立重放） |
|---|---|---:|
| 无干扰 | 自主9步达成Rusty＋Fog，并完成结束阶段 | 72 |
| 原方案受阻 | Scythe第5步收益被无效；继续原动作，到第8步缺少Greaves连接素材 | 43 |
| 自主恢复 | 从第5步后的实际闭链窗口搜索，改为检索并特召Boots，达成同一目标 | 55 |

每组上限512，总计170／1536。恢复独立重跑中断前缀，费用如实计入；没有从后续继续执行、消耗资源的受阻终点恢复。两次冻结候选和恢复方案ID、分组账本一致。这里未开展48手正式评估。

运行原生集成测试：

```text
cargo test --offline -p ygo-planner --test first_turn_autonomous autonomous_generated -- --ignored --nocapture
```

需已准备冻结资产、本机开发worker配置和快照。报告及持久账本保存在本地 `data/runtime/tournament-2026/pilot-autonomous/<run>/`，不提交卡库、引擎产物或运行报告。重复实验另外收费。

局部报告v1记录实际起点、冻结方案、每个显式选择之前的检查点、结构化候选比较、费用及预计资源变化、后续用途、实际差异、灰后锚点和独立查询／整条线路重放引用。方案重新计算知识、目标、限制、起点及完整语义步骤身份；执行合同逐项核对持久调用结果、原始前缀、实际查询和目标。导入报告还须通过 `replay_partial_execution` 重新取得原生查询，不由JSON授予资格。

同名实例身份未知时，数量事实可以保留；依赖该身份的源、费用、对象或素材动作停止。失效别名不能转绑到新出现的同名卡。未知历史属性不由终场查询反填。发动源费用前手牌快照与支付后的墓地快照分别保存。

局部验证器已覆盖成功线路、原方案受阻、必要实例未知及预测差异等记录。其余失败类别虽可保留诊断报告，尚不能取得完整局部合同验证。首步预算截断已有3／4次原生测试，首批新依赖已有指定分支资格；处理中截断、引擎失败、其余74项规则、正式v6合同／CLI、48手可恢复编排及最终干净部署仍待交付。局部成功不会绕过正式覆盖关口。
