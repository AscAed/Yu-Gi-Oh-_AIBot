# 首回合全局最优性研究定义

日期：2026-10-19。依据[产品愿景](PRODUCT_VISION.md)的COMBO-02、COMBO-03、KNOW-02与TRUST-01。**本文是待验证的研究问题与关口，不是已实现算法、schema或可交付承诺。**任务入口见[实施计划P1](superpowers/plans/2026-10-19-product-evolution.md)。

## 研究问题与信任边界

给定冻结规则、禁限表、完整合法卡组、合法起手、引擎及脚本、明确对手资源与合法干扰范围，以及用户定义的目标优先级，寻找首回合策略，并证明问题范围内不存在更优的合法策略。当前beam搜索会裁剪动作和前沿，有限人工语义也未完整覆盖；两者只能给出有界候选，不能承担该证明。

执行权威仍是被冻结的引擎实现。最优性声明相对于其精确版本和所声明规则，不额外声称形式化证明了引擎自身无缺陷，或穷尽现实世界的全部裁定。替换引擎、脚本、随机语义或信息模型会改变证明问题，须重新验收。

## 必须冻结的输入

| 项目 | 研究约定 |
|---|---|
| 卡牌/规则范围 | 正式OCG/MR5，绑定发行截止日、区域、禁限生效日、CDB、Lua及引擎身份 |
| 己方输入 | 完整主/额外/Side、五张实际起手、已公开信息；Side仅按声明场景使用，不隐含换备策略 |
| 对方输入 | 明确可用资源及响应规则；资源是共同已知还是仅对方知道须写入信息模型，缺省研究案例使用共同已知的固定资源 |
| 观察 | 分别定义双方在每个提示能观察到的事件、区域、历史、公开选择和自身私有信息 |
| 随机性 | 牌库在已知信息条件下的合法分布、抽牌/洗切/随机效果的分布；seed仅用于复现，不能作为策略输入 |
| 目标 | 用户顺序的目标/收益向量、各分量定义/取值范围/方向、终场时点；不能暗加胜率解释 |
| 终止 | 引擎判定合法胜利/失败/平局时自然终止；否则首回合结束阶段必要处理全部完成并到达明确下一回合边界。提前出现目标本身不是终场 |
| 求解与校验资源 | 节点、时间、内存、原生调用及校验证据预算；资源上限不改变游戏问题本身 |

底层初始化需要精确记录卡片实例，但数学上等价的同名起手可归组，前提是证明不改变可见信息、概率、次数和合法策略。全合法起手统计按多重集及其抽取概率处理，不能把每个不同名称组合等权计数。

每个目标分量必须预先定义对正常回合终场及提前胜/负/平的评价规则；缺少自然终止评价的请求不能进入最优性证明。胜负事实取引擎合法结束事件与可证状态，不自动插入用户未选择的胜率优先级，也不能将合法提前结束改成“未到结束阶段”而删除分支。终止后不再生成抽牌/响应；确实缺失必要观察时阻断证明，不猜目标值。

## 策略、目标与随机性

策略是从可见历史到合法动作的映射，必要时允许混合策略。具有相同信息的历史必须采取一致决策或一致动作分布；内部知道完整牌序的引擎/校验器不能把该信息泄露给求解策略。抽到新信息后允许按新观察分支。

对每个目标分量先定义期望值，再按用户优先级对期望向量作字典序比较。在固定起手和声明的信息条件下，研究口径可记为：

```text
max(己方合法信息策略) min(对方合法信息策略)
    E[用户目标向量 | 双方信息模型与合法随机分布]
```

这是待求解问题定义，不是声称已有通用求解器。对方同样不能提前观察未来随机结果；不得对每个随机终点分别挑一个全知对手，再误称为同一信息模型的最优应对。若目标向量存在无界或期望未定义分量，先分类，不能套用有限数值排序。

证明计算必须采用精确概率/值或带可核验误差界的表示。数值近似只能说明相应精度的结果；未闭合的误差区间不能宣称精确全局最优。随机抽样和固定seed重放都不等于穷尽随机策略。

## 四类证据必须分开

| 证据 | 能证明什么 | 不能替代什么 |
|---|---|---|
| 来源/知识证据 | 规则候选绑定的正文、脚本、条件与定向案例 | 全状态语义等价、搜索完整性 |
| 原生执行与独立重放 | 记录的选择、状态转移和线路可执行 | 未走分支中不存在更优策略 |
| 搜索完整性证据 | 必要合法动作、信息集、随机/对手分支均被覆盖或安全排除 | 未核实的评分、终场与概率定义 |
| 值界与策略证据 | 可执行策略的保证值和相容上界闭合，排除更优合法策略 | 不同资产/目标/信息模型下的结论 |

单玩家确定性小案例可用完整枚举核验；对抗/随机策略需验证可实现的己方策略及匹配的对抗值界，不能用一条幸运线路的得分当策略下界。校验器独立于候选排序及求解过程，允许信任相同冻结引擎，但须重新检查其使用的动作、概率、界和引用。

## 方法选择与安全剪枝

| 路线 | 可复用之处 | 具体风险/研究结论要求 |
|---|---|---|
| 逐卡人工模型 | 现有知识包、因果转移、真实正反例 | 逐卡成本高；案例不能证明任意上下文；须与完整动作路径交叉验证 |
| 完整引擎搜索 | 原生合法提示、前缀重建和重放 | 合法组合枚举、随机分布、隐藏状态、循环及证据体积仍未解决 |
| 语义+引擎+证明层 | 语义安排探索顺序，引擎执行，另校验分支及值界 | 推荐实验方向；排序可启发式，丢弃分支必须有独立安全理由 |

现有规则知识可用于建议、排序及探索，不直接成为证明资格。证明模式不能使用无上界的beam淘汰、未验证的语义过滤或学习模型分数删分支。只按可见终场合并历史会遗漏次数、限制、随机状态和实例差异；任何合并须证明对未来策略与概率等价。

需要首先核对worker是否枚举了所有合法响应，包括选卡组合、顺序、区域、数值和可选/强制响应；不能把UI提供的一项动作描述当成所有合法编码。未知提示或未支持消息直接阻断相应完整性证明。

## 循环、终止与结果分类

先研究首回合中可重复状态、有限资源循环、收益递增循环及不终止策略。循环等价必须包含完整相关状态/历史和信息分布，不能用可见场面相同代替。对规则允许的循环处理、终止策略集合和评价须给出精确来源及模型；不能静默加入强制结束规则。

以下为拟议概念分类，不修改现有VerificationLevel或报告字段：

- 已证明最优：合法策略、动作/概率完整性、终场和值界全部通过。
- 已验证候选但最优性未证明：有可执行结果，但其余分支或上界未闭合。
- 覆盖缺口：动作、规则、信息、概率或终止模型缺失。
- 预算截断：保留前沿、现有策略、上下界和差距，不等同于无解。
- 已证明无可行目标：仅在完整问题证明目标不可达时使用。
- 已证明无有限最优值/最优值不可达：须有循环或极限论证；不是“程序跑不完”。
- 证据无效或执行故障：原始失败、消费与未决调用保留，不能转成规则否定或成功。

## P1实验及停止条件

1. **动作完整性审计：**按提示种类列出现有解析和枚举的遗漏；构造可由引擎到达的小场景，独立枚举响应对照。发现遗漏先报告，不扩大能力声明。
2. **确定性小问题：**完整合法牌组、明确目标及可完整检查的游戏树；枚举全部必要动作，独立核对最优值和证据。包括正常回合终场及首回合中提前胜/负/平，核对各自目标值和终止后无后继动作。若人为限制动作/深度，必须把它命名为受限问题。
3. **隐藏信息与概率：**至少覆盖相同观察、不同牌序的小案例和一次随机效果；同信息决策一致，概率质量合计为1，拒绝seed泄露策略。
4. **对手与循环：**指定资源的合法响应、无效响应负例；再加入可重复状态/资源变化案例，分别验证循环处理和终止声明。
5. **独立校验与规模报告：**故意移除更优分支、伪造概率/值界/观察、修改资产和目标，均须拒绝；报告CPU时间、调用、峰值内存、证据体积和增长趋势。

每个实验是独立可验收的小任务。先列问题定义及预算，再运行，保留失败；不要求一次研究解决全部提示或卡牌。若完整枚举、信息模型、循环或值界任一基础不能成立，P1结论应列明确障碍与下一项最小实验，P7证明集成保持不可启动。产品基础工具仍可推进，但最终AI验收不通过。

小问题成功只允许启动下一规模实验。代表机制通过不证明全卡；全卡逐效果测试也不证明所有组合。P8必须额外提供覆盖全部合法输入及其交互的方法和可核验证据，否则继续保持未达标。时间/硬件成本尚无足够实测，不承诺全卡证明的完成日期。
