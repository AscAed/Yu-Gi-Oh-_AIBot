# 产品愿景与验收目标

确认日期：2026-10-19。本文件是产品目标的唯一事实源，记录用户原始需求及本轮选择；**不是已实现功能清单**。当前任务见[任务表](../TASKS.md)，差距见[项目评估](PROJECT_ASSESSMENT.md)，阶段依赖见[路线图](ROADMAP.md)，具体任务见[实施计划](superpowers/plans/2026-10-19-product-evolution.md)。

## 产品定位与使用流程

面向普通玩家和专业研究者的中文游戏王OCG卡组研究助手。两项核心能力是构筑卡组与使用卡组推演Combo，并通过可复核的引擎评估形成“构筑 → 推演 → 比较 → 改良”的闭环。ocgcore或经过兼容验收的替代引擎是卡效执行权威；知识体系不能成为自行编写卡效的第二套游戏规则。

普通用户的目标流程：启动本机浏览器界面 → 搜卡/导入/新建牌组 → 编辑或提出主题、字段、指定卡和约束 → 查看互动依据与构筑候选 → 设置目标和干扰情景 → 查看展开、妥协和薄弱点 → 比较构筑 → 保存/导出。专业用户另外能够配置预算、资产版本、知识包和经过验收的引擎适配器。

基础搜卡、编辑及已安装资产上的引擎分析离线可用。联网用于更新及用户选择的云端模型；本地或云端模型均为可选交互层，缺少模型不能阻断基础流程。中文自然语言先转换为可查看的结构化目标/约束，再调用正式功能；不得把模型回答作为执行或证明证据。

## 已确认的产品取舍

- 先交付可操作的基础工具，采用本机浏览器界面；这些是预览成果，不等于最终AI验收。
- 最终AI以冻结版本的全部正式OCG卡牌为覆盖门槛。限定主题、代表卡组或48手通过不能替代这一门槛。
- 最优性研究先限首回合和明确对手资源/干扰情景；后攻、多回合、完整对局及任意对手为后续扩展，不混入本轮证明范围。
- “更优”由用户指定的终场目标及指标优先级定义，不采用暗含实战胜率含义的统一评分。
- 随机结果按合法条件分布计算期望；对指定对手的合法策略采用最坏情景。双方策略均受各自可见信息约束，不允许先看牌序再选动作。
- 只有问题范围内的全部必要分支已检查，或其排除有可核查的安全依据，且上界与可执行策略值一致，才声称全局最优。详见[最优性研究](OPTIMALITY_RESEARCH.md)。
- 大模型可提议主题映射、知识候选和解释，不能签发引擎验证资格或最优性资格。

## 全卡、更新与版本边界

全卡分母是某一截止日期已经正式发行、属于OCG/MR5范围的卡牌清单，逐卡记录来源与证据；Rush、Skill、同人和未正式发行占位卡不混入。禁卡仍可搜索并保留知识，但当前合法构筑不能使用；规则要求的Token/衍生物也须列为引擎依赖，不能因不进入牌组而遗漏其行为。

上游有独立发行库及预发行库，当前仅导入单个cards.cdb不能自行证明全卡完整。[BabelCDB来源说明](https://github.com/ProjectIgnis/BabelCDB)是发现入口；正式发行及区域身份另核对。卡号、同名别名、脚本及语言显示数据分开管理；中文来源、授权和完整度尚需落实，不以机器译文冒充已核对正文。

更新默认在启动时、程序运行期间每小时及用户手动操作时检查；离线不重复报错阻塞。公布日、生效日、获取时间分开记录，未来禁限表不得提前改变默认合法性。禁限依据以[OCG官方名单](https://www.yugioh-card.com/japan/event/limitregulation/)核对；脚本来自[CardScripts](https://github.com/ProjectIgnis/CardScripts)。

新数据先进入候选资产组，校验来源、依赖、兼容性及受影响知识/证据后启用；失败保留上一稳定版本。新卡可先显示为“待分析支持”，但不得借此维持“当前全卡深度支持”的宣传。旧任务和报告始终绑定原资产，更新不会改写历史结论。上述频率不是上游发布后立即完成深度认证的时效承诺。

## 最终验收与成功标准

最终验收必须同时满足上表的产品流程、全卡覆盖和证明要求，不能只验其中之一。对冻结合法卡组的全部合法起手，需要可核查的覆盖方法；随机抽样用于发现问题，不证明全覆盖。卡牌级案例通过也不证明任意卡牌组合、策略或搜索完整性。

合法策略的原生执行及独立重放证明其可执行性；最优性证明另外覆盖未采用动作、对手策略、随机分支、信息一致性和结果上界。遇到未知或资源耗尽可以保存研究进度，但该问题仍未达到最终最优性验收。

终场包含正常完成首回合处理，以及引擎判定的提前胜利、失败或平局。目标向量对每类终止均须有预先定义的评价；不能为追求某一固定场面而删去合法的提前结束分支。

循环、无界收益、只有上确界而无可达最优值等情况须按研究合同分类。不得任意限制操作步数后，把受限结果称作原问题的全局最优。若可行性实验不能建立必要方法，保持最终目标未达标，记录障碍和替代方案，不能自行降低用户要求。

构筑改良按已声明候选范围给出证据，不额外承诺所有合法构筑中最优；全局最优要求针对上述Combo问题。普通用户完成离线基本流程、专业用户替换引擎及中文体验也各有独立验收。公开分发前另完成逐资产许可/notice检查。

## 变更规则

目标改变先修改本页，再同步研究定义、路线和任务表；状态变化不在本页滚动复制。不得因短期研究困难或单主题交付而把全卡、隐藏信息或全局最优要求悄悄降级。历史讨论来源是用户引用的“游戏王AI汇总文档”对话及本轮确认；对话只用于需求追溯，实现事实仍以代码、合同和实跑证据为准。
