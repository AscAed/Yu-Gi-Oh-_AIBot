## 方案比较与关键判断

1. **继续逐卡扩充人工模型：**复用现有知识、账本与正反例，适合完成P4和定向规则；全卡维护和交互组合成本未验证，不能由案例推出安全剪枝。
2. **完整引擎搜索：**保留执行权威；须补齐全部合法动作、随机分布、信息一致性、循环与值界。当前进程前缀重放和beam不是这样的求解器。
3. **语义模型、引擎执行与独立证明结合：**推荐作为P1实验方向。语义先改善排序；只有可核查的安全依据才能删去证明分支。若实验失败，记录障碍而非改称有界最优已满足需求。

近期应同时建立P1研究定义/小实验和P2中文来源基础，P3做普通用户工具，P4保留既有严谨门禁。详细依赖见[路线图](ROADMAP.md)，细任务见[实施计划](superpowers/plans/2026-10-19-product-evolution.md)。

## 系统边界

- ocgcore 是效果结算权威；人工知识负责生成有限预测/候选，不能覆盖或伪造引擎事实。
- 搜索和评分是不同维度。评分是 profile 定义的启发式，不能称胜率或实战强度。
- engine verified 仅适用于所需输入、提示、状态、结算与独立重放均完整的报告。未知关键消息、未知规则、报告不一致、故障和预算不足必须降级或拒绝。
- 线路可执行、知识可信度、搜索完整性及全局最优是四个维度；独立重放不能证明不存在更优分支。概率/循环与证明范围见[研究定义](OPTIMALITY_RESEARCH.md)。
- 数据、引擎、规则表、知识包、Schema、profile、预算和报告都应可追溯到版本/哈希。
