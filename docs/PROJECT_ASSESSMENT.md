## 系统边界

- ocgcore 是效果结算权威；人工知识负责生成有限预测/候选，不能覆盖或伪造引擎事实。
- 搜索和评分是不同维度。评分是 profile 定义的启发式，不能称胜率或实战强度。
- engine verified 仅适用于所需输入、提示、状态、结算与独立重放均完整的报告。未知关键消息、未知规则、报告不一致、故障和预算不足必须降级或拒绝。
- 线路可执行、知识可信度、搜索完整性及全局最优是四个维度；独立重放不能证明不存在更优分支。概率/循环与证明范围见[研究定义](OPTIMALITY_RESEARCH.md)。
- 数据、引擎、规则表、知识包、Schema、profile、预算和报告都应可追溯到版本/哈希。

## 当前环境判断

普通本机包于2026-10-19刷新。2026-10-29只读检查记录包内CLI/worker哈希与`build-hashes.json`一致，doctor为ready、`smoke_ok=null`；旧包没有workbench命令。开发版工作台没有进入旧dist，哈希一致不代表当前源码已部署。当前源码的doctor通过worker执行ABI探针；对旧包那次doctor的内部进程副作用，已有记录不足以确认具体旧二进制行为，见[TESTING](TESTING.md)。

普通包仅带普通资产及Phantom知识；赛事配置引用独立冻结资产和debug worker；本轮独立账本固定案例与重放通过，不代表“正式v6/双资产包已部署”。本次仅检查保存的Ground Collapse来源报告和交付记录，`execution_ready=false`及证明资格false；它不替代现场引擎行为验收。正式源码、普通dist、赛事资产和被冻结的原生runner须各自绑定身份。

Rust/Python、既有编译产物及两套引擎资产为后续离线工程提供基础。`ygo-cli workbench serve`已有本机loopback草稿HTTP/单页界面；通用分析服务、产品化依赖审查和可移植发布包仍待验证。中文候选字段存在性和来源已盘点，但语义、zh-SC类别、别名、字段映射及使用依据未通过。此前硬件CIM读取权限受限，没有取得可用于全卡成本估算的硬件报告，不能据此宣称当前机器足以完成全卡证明。

`data/runtime`及`data/tmp`混有资产与账本证据；`target`同时包含编译缓存和历史交付证据。本轮做过有85处访问盲区、未去重硬链接的只读容量清点，不能视为精确占用；之后仅移除了隔离Cargo缓存。保留/分发边界及范围见[环境审计](ENVIRONMENT_AUDIT.md)。
