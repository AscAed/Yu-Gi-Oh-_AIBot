# 搜索与评分

确定性 beam search 枚举引擎提示的响应；每个新前缀从同一卡组、固定起手、seed 和资产版本重新执行。缓存键包含完整历史，绝不以可见场面合并隐藏效果次数、限制或随机状态。

先求直接结束回合基线；单选提示由 worker 连续执行并记录。beam 先按中间评分和前缀哈希排序，再在不同召唤／发动历史之间轮流分配名额，避免支付费用中的路径被立即丢弃。这个分组仅控制裁剪，不是状态去重或合法性证明。每层还根据 beam 名额轮换预选响应，减少区域变体的执行成本；所有未执行选择计入 pruned。复杂分支和区域选择仍可能因 beam 预算被裁剪。

默认 top_k=5、节点=10,000、beam=32、决策深度=64、总时限=60 秒、单 worker 至多 30 秒且不超过剩余时间。节点表示一次完整前缀执行，决策深度包括自动单选。最后约 10% 时间留给独立重放。节点预算回归可复现；实际触发墙钟限制时返回的线路数可能变化。没有完成且重放成功的线路则空结果并明确 termination。

所有推荐线路独立重放，比较 status、raw/events、终场和 Lua 加载哈希。输出是“当前预算与评分下的最高排名线路”，不证明全局最优。结果保留解释、覆盖缺口、失败分支、缓存命中、最大深度、峰值 frontier、引擎调用次数和耗时。Windows 报告父进程与单 worker 的峰值工作集，两个峰值不等同于同一时刻的总内存。

配置来自 configs/scoring.toml。公式为 `5×互动估计 + 3×资源差 + 2×续航估计 − 0.25×决策数`。资源统计双方手牌／场上卡片差，不把超量素材额外当作卡片资源。版本化 rabbit-v1 对霍普共用素材的攻击无效估计上限为 2；手牌救援兔作为续航估计。普通怪兽、珍珠和 LAN 无互动能力贡献；未覆盖效果/魔陷计零并列为缺口。无对手行动测试的互动保持 heuristic 标签。

旧静态 LineCandidate 排序保留作原型兼容；产品 CLI 使用真实 combo::search，不调用静态模拟。
