# 游戏王AI产品演进实施计划

> 执行者先读[产品愿景](../../PRODUCT_VISION.md)、[最优性研究定义](../../OPTIMALITY_RESEARCH.md)和[当前任务](../../../TASKS.md)。按下述可独立验收任务推进；本轮已交付文档，未来工程任务尚未执行。计划内容本身不授权实施产品功能；后续范围以用户当前指令为准。

**目标：**将中文卡组工具、可信Combo/构筑闭环和全卡最优性研究拆为可复核的小任务，保留最终全OCG与全局最优要求。

**架构：**复用Rust领域/存储/知识/目标/规划/引擎边界；产品服务和浏览器界面在其上编排。语义提供候选与排序，引擎执行，证明层另行核验完整性，Python承担离线数据与评估工具。

**技术基线：**Windows x64、Rust 2021 workspace、Python 3.10+、SQLite/CDB、版本化JSON、隔离ocgcore worker。Node/npm在本机可调用，但尚无前端或HTTP工程；具体框架在P3微型设计中验证，不在本文虚构现有服务。

## 全局约束与执行方式

- 以[产品愿景](../../PRODUCT_VISION.md)的需求编号为规范；当前状态仅写TASKS，实跑证据只追加TESTING，历史计划不覆盖新目标。
- 普通资产与赛事隔离资产不混用，v1–v5身份/读取/重放保持兼容；正式v6、通用知识和证明合同分别版本化。
- 基础操作离线，模型可选；模型输出不能认证卡效或剪枝。普通用户界面用中文，机器接口使用稳定卡号及版本。
- 最终要求是全部正式OCG和首回合明确情景的全局最优证明；中间预览、固定样本、v6完成均不能冒充最终验收。
- 外网终端操作同次调用注入127.0.0.1:7897代理；离线测试无需代理。外部卡库、脚本、图像、DLL及个人路径不提交。
- 后续实施每次只领取一个下述任务：先明确输入/产出和失败用例，再实现并验证；记录结果和下一任务，不跨关口批量开发。
- 不承诺总工期。任务过大时沿独立验收结果继续拆分；每次实测后更新成本估计，不降低目标换取“完成”。

本计划最初是2026-10-19产品路线分解。此后P0首批身份/构建记录、覆盖清点、研究输入工具和P1/P2部分专项已交付，但完整发行分母、研究门禁及后续产品阶段仍未完成。下列复选框保留原任务定义，不同步实时完成状态；当前状态以[TASKS](../../../TASKS.md)为准，近期工作顺序见[2026-10-27项目再规划](2026-10-27-project-realignment.md)。

## P0：目标、分母和可复核基线

- [ ] **P0.1 全卡分母清单。**输入固定发行截止日、官方发行/区域依据和全部相关数据库来源；产出逐卡来源、正式卡号、别名、依赖、正文/脚本身份与缺口清单。检查独立发行库、预发行排除及规则生成物，禁止用13,665或14,731行作为完整性证明。验收：重复来源、卡号迁移、未知发行和缺失脚本均有明确处理。
- [ ] **P0.2 工作区/资产身份采集。**输入源码HEAD、实际工作区内容和两套配置；产出不包含个人路径的身份摘要，能区分提交、未提交源码、构建产物和运行资产。验收：改一个源码/worker/脚本可定位失配；doctor通过不替代构建来源证明。
- [ ] **P0.3 研究输入及成本协议。**按研究定义冻结目标、观察、概率、终止和资源口径；产出P1各实验的独立案例说明与预算。验收：固定seed未被当成已知牌序，最优性与引擎执行证据分别记录。

退出：需求、覆盖分母定义与实验问题均可追踪。先定义清单格式和案例范围即可启动小实验，完整全卡核对逐批推进；P8要求清单最终完整。

## P1：最优性研究可行性关口

- [ ] **P1.1 动作枚举审计。**逐提示核对合法响应编码、组合、可选/强制分支；输出支持矩阵及原生正反例。验收：被省略的合法组合会使完整性校验失败，未知提示不能跳过。
- [ ] **P1.2 确定性完整小问题。**用引擎可到达场景建立完整树与独立最优值对照；输出策略/值界证据原型。验收：删除一条更优分支或换目标后拒绝证据；正常终场及首回合提前胜/负/平的目标值均已定义，终止后不生成后继动作；受限问题不外推。
- [ ] **P1.3 信息与随机策略。**加入未知牌序、抽牌/随机效果及指定对手资源；输出条件概率与信息一致策略。验收：同观察不同隐藏状态不得采用全知决策；概率、己方保证值和对方上界可复算。
- [ ] **P1.4 循环与独立校验。**测试完整相关状态重复、资源增长、不可达最优及中断；输出分类、证据校验与规模报告。验收：伪造概率/值界/循环等价被拒绝，预算耗尽只标未证明。

退出：每项实验有通过或明确失败结论、成本与下一步。基础缺失则暂停相应证明集成，记录最小修复实验；不暂停无关产品基础。通过只意味着可进入更大实验，不承诺全卡可算完。

## P2：中文数据与版本更新基础

- [ ] **P2.1 中文来源与映射。**核验中文名称/正文/别名/字段数据的取得方式、版本和许可；产出语言包与缺口报告。验收：卡号关联稳定、同名歧义可见；无中文来源时不能假称已覆盖。
- [ ] **P2.2 查询服务。**支持中文名称/别名/正文、主题字段、卡号和类型过滤；检索结果同时返回来源、版本和覆盖。验收：简繁/别名差异、无结果、缺失译文和混合主题；解释层与引擎目录不串改。
- [ ] **P2.3 候选更新与回滚。**实现启动/每小时/手动检查、候选资产组、受影响范围检测与稳定版本切换。验收：网络/代理失败不破坏离线使用，未来生效禁限表不提前启用，已有任务固定旧快照。

退出：已核验范围的中文检索与可回滚更新可用；未支持新卡明确显示。全卡中文完整度仍按P0分母逐批统计。

## P3：卡组工作台与本机浏览器

- [ ] **P3.1 牌组文档与往返。**复用现有卡号与主/额外/Side结构，区分草稿保存和完整合法性门禁；实现YDK/JSON导出及导入往返。验收：残缺/空草稿可存、未知卡可诊断；不能把不足40张当成完整合法牌组，也不能丢失重复数量或Side。
- [ ] **P3.2 编辑与约束。**新建、增删、数量修改、保存、锁定卡和数量范围；产出可恢复的用户牌组文档。验收：候选不能覆盖用户原稿，非法状态可解释，锁定约束贯穿后续构筑。
- [ ] **P3.3 本机服务与界面。**先形成微型设计并验证前端/服务依赖；再交付中文搜卡、编辑、分析任务进度和结果查看。服务仅本机访问，重型引擎任务与界面请求分离；不用shell执行用户自然语言。验收：启动/停止、错误、取消及无模型流程可操作。
- [ ] **P3.4 可选中文指令层。**把中文请求转换成可核对结构化意图，支持用户自行配置本地/云端模型。验收：模型不可用时基础功能正常；不自动上传牌组，发送范围在启用云端时说明；模型断言不能变成规则证据。

退出：普通用户可完成离线搜卡及编辑/导入导出，已支持分析可提交和查看；界面明确各能力范围。该成果是工作台预览，不是最终AI。

## P4：保持现有v6收尾的R1–R5门禁

- [ ] **P4.1/R1 可靠执行恢复。**先补失败矩阵，再接真实执行安全检查点；验收连续/暂停重开结果、计划身份、首次预测、账本和独立重放一致，未知消费不退款。
- [ ] **P4.2/R2 逐组语义认证。**按资源循环、召唤/素材、连锁改写、持续限制、延迟处理拆组；每组独立正反例与原生审计，不把102条分类当86项实现。依赖的规则未认证即拒绝。
- [ ] **P4.3/R3 正式v6。**完成请求/报告/CLI版本分派和覆盖门禁；验收旧v1–v5身份/重放不变，预测、实际与响应比较分开。
- [ ] **P4.4/R4 冻结16+32。**冻结独立人工基准、功能/赛事样本、策略和预算，再执行可恢复评估；验收未知/未触达/非法响应/失败/截断分类及汇总独立重算，不外推胜率。
- [ ] **P4.5/R5 干净双资产部署。**完整测试、opt-in原生案例和旧/新重放后，在独立干净checkout构建双资产包，比较身份/账本；不能以普通dist刷新代替。

专项细节沿用[2026-10-17 v6计划](2026-10-17-first-turn-v6.md)的场景、预算和历史证据；其“HTTP/UI暂不做”仅约束该专项，不再阻止P2/P3独立推进。退出后只声明新本家指定范围v6验收。

## P5：可扩展知识与机制覆盖

- [ ] **P5.1 效果关系与证据合同。**定义效果、条件、费用、对象、次数、触发、持续/延迟限制及资源关系；产出带源版本、失效关系和证据引用的概念模型，再进行独立schema设计。
- [ ] **P5.2 候选提取/审阅流程。**从正文、脚本和引擎观察生成候选，人工或工具审阅后定向原生验证；验收来源失配撤销受影响资格，失败和反例保留。不能假设静态Lua提取天然完整。
- [ ] **P5.3 跨机制迭代。**逐批加入融合、仪式、同调、超量、灵摆、连接及相关规则；每批交付关系查询、实际案例和覆盖差距。代表集成功不能代替P8全卡及组合证明。
- [ ] **P5.4 输入牌组识别。**输入卡组、目录/语言映射、知识版本，输出主题/字段集合、玩法假设、关联互动、依据和未知清单。区分实际setcode、主题词典映射与玩法推断；覆盖混合主题、共享组件、稀少线索和未知牌组，不强制指定单一主题，不凭识别结果自签互动资格。验收：同一牌组重复结果可复核；更换证据版本可定位差异；未知须披露而非套用熟悉主题。产出供P6构筑诊断及P7分析使用。

退出：新机制可通过同一流程扩展，知识和剪枝证据分离；未知关系不能支持确定性推荐。关系查询和候选生成可先于全卡知识完整交付。

## P6：构筑与Combo反馈

- [ ] **P6.1 指定卡互动查询。**解释多卡互动、可检索对象、资源用途及限制，绑定证据；验收“可能关联”不写成必然可发动。
- [ ] **P6.2 残缺补全与主题构筑。**用户主题/字段、锁定卡及数量约束进入候选生成；先实现小范围补全，再实现从空牌组构筑。验收合法性、冲突解释和未知范围，不静默删除约束。
- [ ] **P6.3 小范围替换比较。**冻结候选、目标和对手情景，使用相同起手抽样方法、种子计划与预算做配对评估；不同卡组的起手概率按各自牌组计算。验收避免只挑有利起手，增加预算的结果不当构筑收益。
- [ ] **P6.4 留出集和反馈报告。**探索/选择用开发样本，最终比较用独立留出样本；报告原构筑与候选的目标达成、最坏响应损失、恢复、未知及成本。没有统计支持不能称已显著改良或全局最佳构筑。

退出：支持范围内可重复完成“编辑/构筑 → 推演 → 比较 → 导出”，清楚区分工程预览与最终目标。

## P7：通用干扰、概率策略与证明集成

- [ ] **P7.1 干扰类型逐项扩展。**每种干扰先独立原生合法/非法响应，再做响应点比较、闭链后的实际恢复；多次干扰另作任务，不能由单灰外推。
- [ ] **P7.2 薄弱点与策略比较。**同一目标/资源基线比较所有声明范围内的合法响应点和恢复策略，损失度量来自用户目标向量；未知列阻止“最大损失点已证明”结论。
- [ ] **P7.3 接入完整性方法。**在P1验证基础上增加问题规模，保留未知信息策略、条件概率、合法动作及安全剪枝证明；候选搜索与证明搜索分别留证。
- [ ] **P7.4 独立证明验证与恢复。**核对策略、上下界、终止/循环、资产/目标引用及检查点；验收篡改、截断、遗漏和循环负例。新合同不得伪装为旧engine_verified状态。

退出：每个已证明结果都有可核查的问题范围和证据；剩余输入仍标未证明。该阶段不因部分结果通过而完成全卡承诺。

## P8：全卡与产品最终验收

- [ ] **P8.1 全量覆盖审计。**按P0冻结分母核对每卡/效果/依赖/必要规则及跨卡交互方法；全部合法卡组/起手的覆盖方法须可检查，不能用逐卡单例或随机样本替代组合完整性。
- [ ] **P8.2 增量发布门禁。**更新导致的卡号、正文、脚本和规则变化触发关联证据失效及重验；公布稳定版本覆盖范围，未认证新卡不能维持全卡支持声明。
- [ ] **P8.3 易用部署、双语与引擎适配。**普通用户在干净机器准备获许可资产后可启动；路径迁移有诊断；中文普及后完成英语切换。替代引擎必须通过能力协商、事件合同、真实行为与证明一致性验收，不能只换DLL。
- [ ] **P8.4 发布审查。**完成逐资产来源、版本、许可证/notice、修改和再分发清单，以及公开包内容核验。DATA/DECK/BUILD/COMBO/KNOW/ENG/LANG/UX/TRUST各需求均有可核查证据才接受最终交付。

### 每项任务的证据与复估

每个未来任务执行前冻结案例，完成后向[TESTING](../../TESTING.md)追加源码/工作区/资产身份、命令、结果、限制及原始证据引用。工程行为改动用focused测试和必要原生回归；本次纯文档不新增测试代码或重跑无关Rust全套。

每阶段至少记录实际耗时、符号展开、引擎执行/审计/重放调用、峰值内存、证据体积和失败/未知数量；缓存、复用、重试及未知消费分别列出。硬件上限与全卡成本尚未核实，不把一次Rabbit耗时线性外推为总工期。

优先审查：同名实例/别名、未来禁限生效、残缺草稿、混合/未知牌组识别、动态效果与限制、隐藏牌序泄露、非法对手策略、提前胜/负/平、收益循环、伪造来源/证明、预算耗尽、留出集污染、引擎切换。具体负例归属于上述任务，不另建独立待办来源。

若中文来源、动作完整性、概率/循环模型、状态等价或校验规模无法落实，记录受阻子目标、已有证据和下一最小实验；P2/P3等无关任务继续。改变最终验收口径必须由用户明确决定，不能由实施者自行降级。
