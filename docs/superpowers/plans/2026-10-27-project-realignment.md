# 项目再规划实施计划：研究与卡组工作台双轨

> 执行者先读[产品愿景](../../PRODUCT_VISION.md)、[当前任务](../../../TASKS.md)、[路线图](../../ROADMAP.md)和[最新Ground Collapse交接](2026-10-27-ground-collapse-preparation-handoff.md)。本次仅交付文档；下列工程、数据和研究任务均未执行。复选框表示未来任务步骤，实时完成状态只维护于TASKS。后续实施按已授权范围逐任务执行，可使用 `superpowers:executing-plans`；本计划本身不授予运行原生实验或提交资产的权限。

**规范：**实验授权、预算和停止条件依[研究运行规范](../../RESEARCH_OPERATIONS.md)；身份、会计、失败与交付证据依[证据合同](../../EVIDENCE_CONTRACTS.md)。历史scope仍使用其原合同，不倒填新规则。

**目标：**先交付可保存、编辑和往返导入导出的卡组工具，同时逐项解除可靠执行和最优性研究的阻断；最终全部正式OCG与全局最优要求保持不变。

**架构：**研究线继续沿Rust引擎适配、证据、规划与独立校验边界推进；工作台复用领域卡号和主/额外/Side结构，以牌组文档为入口。中文来源核验独立推进，界面可以显示已知卡号和明确的缺译诊断，不能因展示候选译文提升语言或引擎资格。

**技术基线：**Rust 2021 workspace、Python离线数据工具、版本化JSON与YDK、本机浏览器。当前没有交付前端/HTTP工程；B2先形成微型设计并核实依赖，不在本计划冒称已有服务。

## 边界、证据与依赖

- 首个产品验收点是**草稿保存、主/额外/Side编辑、YDK/JSON往返**，随后交付最小本机浏览器工作台；不等待P1完整证明、P4全部86项规则或P2正式中文资格。
- 全正式OCG发行分母、全卡支持和全局最优仍是最终关口。工作台预览、有限研究案例及指定profile的v6完成都不能替代最终验收。
- 本轮不实施模块、不构建，不执行doctor、native、runner、worker、FFI或业务verify，不修改部署/active资产，不提交Git或外部数据。未来文中测试命令均为实施时的验证建议，本轮没有运行。
- 本计划新增的接口、模块和测试名均为拟议设计；既有schema、报告和命令行为继续有效。旧v1–v5读取、身份、失败分类与重放兼容必须保留。
- 原生实验按自己的scope、输入、预算、窗口和停止条件授权；不把历史一次性或封存政策泛化为所有开发任务的永久禁止规则，也不借新文件名继续旧实验。
- 最新Ground Collapse只认证离线准备与固定来源：新增native/runner/worker/FFI均0，`execution_ready=false`。实际opcode24提示、掩码及响应接受未知，不能直接把准备报告交给worker。

## A1 / P4-R1a：首次失败诊断的离线聚焦回归

**输入：**`start_partial_v2`、`validate_partial_execution_v2`及journal保存结果/错误的合同。静态观察是：前者在首次`Ok(result)`含`error`或`QueryWitness::capture`失败时保留`last_result`和初始意图；后者仅在`last_result.is_none()`时走`validate_failed_start`，否则拒绝初始失败意图或进入要求查询的路径。**这只是静态不对称线索，尚未实跑复现，不称已证缺陷。**

**输出与交付物：**最小离线复现、明确诊断不变量及修复；保留已收费的真实结果字节，但不把失败初态赋予可信查询、可恢复前缀或成功资格。

- [ ] 在现有默认单元测试中先加入`initial_result_error_retains_a_valid_diagnostic`和`initial_query_capture_failure_retains_a_valid_diagnostic`：内存/合成结果与临时journal，不启动外部进程；断言报告能被独立诊断验证器接受，调用用途/费用与保存outcome一致，成功/可信前缀资格保持否。
- [ ] 运行这两个focused测试，保存修复前结果；若未复现，记录真实路径与反证，先修正问题定义，再决定是否改生产代码。
- [ ] 复现后最小修正首调用分类和验证分派；加入伪造错误码/阶段、替换结果、增加查询或前缀、改费用和缺失意图的拒绝反例，兼顾首次transport错误及预算拒绝旧路径。
- [ ] focused回归通过后运行受影响crate默认测试和格式/Clippy；任何进程替身必须明确为合成，不把外部runner执行包装为“零原生”测试。

**退出：**两类失败均有可验证诊断、篡改被拒绝、费用不退款；诊断通过与引擎资格分离。**失败处理：**保留红测和最小输入，不试跑真实worker求解；扩大失败矩阵时先拆独立任务。**依赖：**D0；不依赖B1/C1/A2。

## A4 / P1：信息概率或循环的单一可行性关口

**输入：**最优性研究定义、明确的有限小问题和已认证必要动作/终止；每批只从下列两类选一类。

**退出：**本问题得到可核查的通过或失败/受阻结论，不是“已有算法就可全卡求解”。**失败处理：**保留未证明与最小反例，阻断相应证明集成；B线继续，最终目标不降级。**依赖：**A2明确所需动作/来源；如不依赖新增提示，可独立安排数学离线批次。
